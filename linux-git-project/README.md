# CoreDataEngineers – Linux, Bash & Git Project

A small end-to-end data engineering exercise built entirely with **Bash**,
**cron**, and **Git** on Linux: a Bash ETL pipeline that downloads, cleans,
and loads a real government dataset, a cron schedule to automate it, and a
utility script to keep a folder tidy — all version-controlled with Git.

## Repository structure

```
coredataengineers-etl/
├── scripts/
│   ├── etl.sh                     # Extract → Transform → Load pipeline
│   └── move_csv_json_files.sh     # Moves *.csv / *.json files into json_and_CSV/
├── cron/
│   ├── README.md                  # How cron works + how this job is scheduled
│   └── crontab_entry.txt          # The actual crontab line (0 0 * * *)
├── sample_data/                   # Example CSV/JSON files to demo the mover script
├── raw/            (generated)    # Step 1: downloaded source CSV lands here
├── Transformed/    (generated)    # Step 2: cleaned/selected columns land here
├── Gold/           (generated)    # Step 3: final "loaded" copy lands here
├── logs/           (generated)    # Timestamped run logs
├── .gitignore
└── README.md                      # You are here
```

> The `raw/`, `Transformed/`, `Gold/`, and `logs/` folders are **generated by
> running the scripts** — they are intentionally excluded from Git via
> `.gitignore` so the repo only tracks source code, not pipeline output.

## 1. The ETL pipeline (`scripts/etl.sh`)

A single Bash script that performs a simple **Extract → Transform → Load**
process against the Stats NZ *Annual Enterprise Survey 2023* dataset.

| Step | What happens |
|---|---|
| **Extract** | Downloads the CSV from the URL in the `CSV_URL` environment variable using `curl`, saves it into `raw/`, and confirms the file exists and is non-empty. |
| **Transform** | Renames the `Variable_code` column to `variable_code`, selects only `year, Value, Units, variable_code`, and writes the result to `Transformed/2023_year_finance.csv`. Confirms the file was created. |
| **Load** | Copies the transformed file into `Gold/2023_year_finance.csv` and confirms it landed there. |

### Design notes

- **Environment variable for the URL**: the source URL is never hard-coded
  into the logic — it's read from `CSV_URL`, which the script exports with a
  sensible default and which can be overridden by the caller (or by cron —
  see below):
  ```bash
  export CSV_URL="${CSV_URL:-https://www.stats.govt.nz/assets/Uploads/Annual-enterprise-survey/Annual-enterprise-survey-2023-financial-year-provisional/Download-data/annual-enterprise-survey-2023-financial-year-provisional.csv}"
  ```
- **Portable CSV parsing**: some columns in the raw dataset (e.g. industry
  names) contain commas inside quoted text — a naive `cut -d','` would break
  on those rows. Instead, the transform step uses a small hand-written
  quote-aware CSV field splitter in plain **POSIX awk**, so it works with
  whatever `awk` happens to be installed (`mawk`, `gawk`, `busybox awk`,
  etc.) — no dependency on gawk-only extensions like `FPAT`.
- **Confirmation at every step**: after each step, the script checks the
  output file exists and is non-empty, logs a `CONFIRMED:` line with the
  file path and size/line count, and exits non-zero on any failure
  (`set -euo pipefail`).
- **Logging**: every run prints progress to the console *and* appends a
  timestamped copy to `logs/etl_YYYY-MM-DD.log`, so scheduled (cron) runs
  leave a full audit trail even when nobody is watching the terminal.

### Running it

```bash
cd coredataengineers-etl
./scripts/etl.sh
```

Optional: override the source URL or base directory:

```bash
CSV_URL="https://example.com/other-file.csv" ./scripts/etl.sh
```

Expected console output (abridged):


## 2. Scheduling the ETL with cron

The pipeline is scheduled to run **every day at 12:00 AM** using `cron`,
Linux's built-in job scheduler. Full details and background research are in
[`cron/README.md`](./cron/README.md); the short version:

```cron
0 0 * * * /bin/bash /full/path/to/coredataengineers-etl/scripts/etl.sh >> /full/path/to/coredataengineers-etl/logs/cron.log 2>&1
```

- `0 0 * * *` → minute 0, hour 0, every day, every month, every weekday =
  **midnight, daily**.
- Install it with `crontab -e` (paste the line from
  [`cron/crontab_entry.txt`](./cron/crontab_entry.txt), updating the path
  first) and verify with `crontab -l`.

## 3. Moving CSV/JSON files (`scripts/move_csv_json_files.sh`)

A standalone utility script that moves **all** `.csv` and `.json` files from
one folder into a destination folder named `json_and_CSV`. It works with
one file, many files, or a mix of both, and safely does nothing (with a
clear message) if no matching files exist.

```bash
./scripts/move_csv_json_files.sh <source_folder> [destination_folder]
```

`destination_folder` defaults to `./json_and_CSV` if omitted.

### Demo

Sample files are provided in `sample_data/` (`customers.csv`, `orders.csv`,
`config.json`, plus a `notes.txt` that should be left behind):

```bash
./scripts/move_csv_json_files.sh sample_data
```

Output:

```
[...] Destination folder ready: 'sample_data/json_and_CSV'
[...] Moved: customers.csv -> sample_data/json_and_CSV/
[...] Moved: orders.csv -> sample_data/json_and_CSV/
[...] Moved: config.json -> sample_data/json_and_CSV/
[...] Done. 3 file(s) moved into 'sample_data/json_and_CSV'.
```

`notes.txt` remains in `sample_data/`, untouched — only `.csv`/`.json`
(case-insensitive) files are ever moved.

## 4. Version control (Git)

All work in this repository is tracked with Git, with incremental commits
per task so the history tells the story of the build:

```bash
git log --oneline
```

To use this repo:

```bash
git clone <your-fork-url>
cd coredataengineers-etl
chmod +x scripts/*.sh
./scripts/etl.sh
./scripts/move_csv_json_files.sh sample_data
```

## Requirements

- A Linux environment (or WSL/macOS) with `bash`, `curl`, and `awk`
  available — no extra packages required.
- `cron` (installed by default on virtually all Linux distributions) for
  the scheduling piece.
